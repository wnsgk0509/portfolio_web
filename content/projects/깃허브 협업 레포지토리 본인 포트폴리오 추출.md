# GitFolio Generator — GitHub 기반 AI 기술 포트폴리오 생성기

URL: https://github.com/wnsgk0509/GitFolio_Generator
도메인: https://gitfoliogenerator-8prcmeheyqi4bt9u9ef4nk.streamlit.app/
기술: Python, Streamlit, PyGithub, Google Gemini API (google-genai), Notion API
날짜: 2026년 09월 23일 → 2026년 10월 12일
팀구성: 개인 프로젝트 (1인 개발)
역할: 기획·아키텍처 설계, GitHub 데이터 추출/노이즈 필터링, Gemini Map-Reduce LLM 파이프라인 및 다중 플랫폼(MD/HTML/Gist/Notion) Export 구현

## 프로젝트 소개

**GitFolio Generator**는 GitHub 저장소의 README, 커밋 히스토리, PR 및 코드 Diff를 자동 수집·정제하고, **Google Gemini API**를 통해 구조화된 한국어 기술 포트폴리오로 변환해 주는 **AI 문서화 웹 서비스**입니다.

- **AI & Backend**: Python, Google Gemini API (`google-genai`), Map-Reduce 청킹 파이프라인
- **Data Extraction**: PyGithub (GitHub REST API, 노이즈 커밋 필터링)
- **Web UI & Export**: Streamlit, 독립형 인쇄용 HTML Exporter, GitHub Gist API, Notion API (네이티브 블록 변환)

## 기획 및 문제 정의

- **해결하려는 문제**: 팀 프로젝트 종료 후 개발자가 수백 개의 커밋과 PR을 일일이 뒤져 본인 기여도와 트러블슈팅을 정리하는 데 큰 시간이 소요되며, 기존 단순 LLM 요약은 커밋 수가 많아지면 세부 기술 맥락이 누락되는 한계가 있었습니다.
- **설계 전략**: 단순 머지·포맷팅 같은 노이즈 커밋을 사전에 걸러내고, 저장소 규모에 따라 **표준 고속 모드(단일 호출)**와 **정밀 분할 모드(40커밋 단위 Map-Reduce)**를 선택할 수 있는 하이브리드 LLM 파이프라인을 설계했습니다.

## 본인 역할

서비스 기획부터 데이터 추출기, 하이브리드 LLM 생성 엔진, 4종 내보내기 파이프라인 및 Streamlit Cloud 배포까지 **전 과정을 1인 주도 개발**했습니다.

- **GitHub 추출 및 노이즈 필터링 모듈(`src/github_extractor.py`) 개발**: PyGithub 기반 저장소 README·커밋·PR Diff 수집 및 단순 머지·무변경 커밋 필터링 파이프라인 구축
- **하이브리드 LLM 분석 엔진(`src/llm_generator.py`) 설계**: 커밋 규모에 따라 표준 고속 모드(최대 80커밋 단일 분석)와 Map-Reduce 정밀 분할 모드(최대 200커밋을 40개 단위 청크 요약 후 5개 섹션 종합)를 전환하는 프롬프트 파이프라인 구현
- **4종 다중 내보내기 파이프라인 개발**: Markdown 복사/다운로드, 브라우저 PDF 인쇄용 독립형 HTML(`src/html_exporter.py`), GitHub Gist 자동 배포(`src/gist_exporter.py`), Notion API 네이티브 블록 직접 전송(`src/notion_exporter.py`) 구현
- **Streamlit UI(`app.py`) 구축 및 실배포**: 분석 모드 선택, 실시간 진행 상태 피드백 및 Streamlit Cloud 배포 완료

## 핵심 기능

- **GitHub 데이터 추출 및 노이즈 필터링**:
  - PyGithub API를 통해 저장소 README, 커밋 메시지, PR 및 코드 Diff 데이터를 자동 수집
  - 단순 머지 커밋이나 변경사항이 없는 노이즈 커밋을 사전 필터링해 LLM 입력 토큰 효율 및 분석 정확도 향상
- **하이브리드 포트폴리오 분석 모드 (LLM 파이프라인)**:
  - **표준 고속 모드**: 최근 유의미한 커밋 최대 **80개**를 단일 컨텍스트로 전달해 약 **15초** 내 빠르게 포트폴리오 생성
  - **정밀 분할 모드 (Map-Reduce)**: 최대 **200개** 커밋을 **40개 단위 청크**로 분할 요약(Map)한 뒤 최종 5개 섹션으로 종합(Reduce)해 약 **40초** 내 초기 아키텍처부터 세부 트러블슈팅까지 누락 없이 추출
- **4종 다중 내보내기(Export) 파이프라인**:
  - **Markdown**: `.md` 파일 다운로드 및 원클릭 클립보드 복사 지원
  - **PDF 인쇄용 독립형 HTML**: 브라우저 `Ctrl + P`로 즉시 이력서/포트폴리오 PDF 출력 가능한 스타일링 HTML 생성
  - **GitHub Gist 자동 배포**: 외부 공유용 Gist URL 원클릭 발급
  - **Notion API 직접 전송**: 마크다운 결과를 Notion 네이티브 블록 객체로 변환해 지정 페이지/DB로 자동 발행

## 기술 검증 요약

- **LLM 파이프라인 비교 검증**: 단일 호출(최대 80커밋, ~15초) 대비 40개 단위 Map-Reduce 분할 모드(최대 200커밋, ~40초)를 실제 협업 저장소(`Provit` 등)에 적용해, 초기 설계·세부 트러블슈팅 누락 방지 및 응답 시간 트레이드오프를 검증
- **다중 Export 출력 검증**: 생성된 마크다운이 HTML 인쇄 레이아웃, GitHub Gist, Notion 네이티브 블록 구조에서 깨지지 않고 변환되도록 4개 채널 실연동 검증 완료

## 기술 검증 및 트러블 슈팅

### 1. 대용량 커밋·Diff 분석 시 단일 프롬프트 컨텍스트 한계 및 세부 내역 누락 문제

- **문제**: 커밋 수가 많은 협업 저장소를 단일 프롬프트로 분석할 때, 입력 토큰 한계와 어텐션 분산으로 인해 초기 아키텍처 결정이나 개별 트러블슈팅 근거가 누락되는 현상이 발생했습니다.
- **원인**: 전체 커밋과 Diff 패치를 한 번에 LLM에 전달하는 단순 구조에서는 저장소 규모가 커질수록 정보 압축 손실이 급격히 증가했습니다.
- **해결**: `src/github_extractor.py`에 `DEFAULT_MAX_COMMITS`(80), `DEEP_MAX_COMMITS`(200) 기준과 노이즈 커밋 필터를 적용하고, `src/llm_generator.py`에 **40개 단위 청크 Map 요약 → 5개 표준 섹션 Reduce 종합** 파이프라인을 구현해 UI에서 모드를 선택할 수 있도록 구성했습니다.
- **결과**: 소규모 저장소는 약 **15초** 내 빠르게 초안을 생성하고, 200커밋 규모의 장기 저장소는 약 **40초** 내 세부 기술 맥락 손실 없이 구조화된 포트폴리오를 생성할 수 있음을 실제 저장소 테스트로 검증했습니다.

### 2. 생성된 마크다운의 외부 플랫폼(Notion/HTML) 포맷 호환성 문제

- **문제**: LLM이 생성한 마크다운 텍스트를 Notion이나 PDF 문서로 옮길 때 코드 블록, 중첩 리스트, 헤더 서식이 깨져 수작업 재편집이 필요했습니다.
- **원인**: 플랫폼별 문서 스키마(Notion Block JSON, 인쇄용 HTML CSS)와 일반 Markdown 문법 간의 구조적 차이 때문이었습니다.
- **해결**: `src/notion_exporter.py`에서 마크다운 요소를 Notion API 네이티브 블록 객체로 파싱·변환하는 전용 어댑터를 작성하고, `src/html_exporter.py`에 `@media print` 기반 독립형 스타일 시트를 내장했습니다.
- **결과**: 생성 직후 클릭 한 번으로 Notion 페이지 발행 및 A4 PDF 출력까지 이어지는 끊김 없는 문서화 파이프라인을 완성했습니다.

## 배운 점 및 회고

- **LLM 서비스 엔지니어링의 핵심은 프롬프트 너머의 파이프라인 설계**: 대용량 코드 데이터를 정확히 다루기 위해서는 노이즈 사전 필터링과 Map-Reduce 청킹처럼 **데이터 전처리·분할·검증 구조**가 품질을 좌우한다는 점을 체득했습니다.
- **사용자 워크플로우 끝단까지 연결하는 Export 설계**: AI가 텍스트를 생성하는 것에서 멈추지 않고 Markdown·HTML(PDF)·Gist·Notion까지 실제 활용 접점을 연결하며 프로덕트 완성도를 높이는 경험을 쌓았습니다.
