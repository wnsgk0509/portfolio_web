# GitFolio Generator

기술: Python, Streamlit, PyGithub, Google Gemini (google-genai), Notion API
날짜: 2026년 09월 23일 → 2026년 10월 12일
팀구성: 개인 프로젝트
역할: 전 기능 1인 개발 (기획/설계, GitHub & Notion API 연동, LLM 파이프라인 구축)

## 프로젝트 소개

**GitFolio Generator**는 GitHub 저장소의 커밋 로그, PR, 코드 diff 이력을 자동으로 분석하여 개발자 기술 포트폴리오(마크다운)를 생성해 주는 AI 기반 웹 애플리케이션입니다.

기존에 수작업으로 오랜 시간이 걸리던 프로젝트 정리 과정을 자동화하여, 실제 기여한 코드 diff와 트러블슈팅 이력에 근거한 신뢰도 높은 기술 문서를 손쉽게 추출하고 Notion, Gist, HTML/PDF 등 다양한 포맷으로 공유할 수 있도록 지원합니다.

- **Language & Runtime**: Python 3.10+
- **Frontend / Dashboard**: Streamlit
- **LLM Engine**: Google Gemini Flash (`google-genai` SDK)
- **External APIs**: PyGithub (GitHub REST API), Notion API (`notion-client`)
- **Export Formats**: Markdown (.md), Standalone HTML/PDF, GitHub Gist, Notion Native Blocks

## 본인 역할

기획부터 대시보드 UI, GitHub 활동 데이터 정제 엔진, 대규모 이력 분석을 위한 LLM 파이프라인 설계, 다중 플랫폼 내보내기 기능까지 전 과정을 1인 개발하였습니다.

- **GitHub 활동 데이터 수집 및 정제 엔진 개발**: PyGithub를 활용해 커밋, PR, diff를 수집하고 토큰 낭비를 유발하는 빈 커밋/단순 머지 커밋을 걸러내는 지능형 노이즈 필터링 구현
- **하이브리드 LLM 파이프라인 설계**: Gemini Flash를 기반으로 단일 고속 분석과 대규모 커밋(최대 200개) 처리를 위한 Map-Reduce 2단계 요약·종합 아키텍처 구축
- **API 안정성 및 장애 대응 설계**: Gemini 503 혼잡 및 429 쿼터 초과에 대비한 지수 백오프(Exponential Backoff) 재시도 및 하위 Flash 모델 자동 폴백(Fallback) 체인 구현
- **다중 플랫폼 내보내기 모듈 개발**: 마크다운을 분석하여 Notion 네이티브 블록으로 변환·전송하는 파서 구현, GitHub Gist 원클릭 배포, A4 인쇄 최적화 HTML/PDF 변환기 구축
- **반응형 웹 UI 및 오케스트레이션**: Streamlit을 활용해 진행 상태 실시간 시각화, 마크다운 실시간 미리보기 및 환경변수 호환성을 지원하는 대시보드 구축

## 핵심 기능

- **GitHub 활동 데이터 정밀 추출 및 노이즈 필터링**:
  - 커밋 & PR diff 분석: 대상 기여자의 커밋 및 PR 패치 데이터를 추출하여 토큰 효율적인 구조로 정제
  - 지능형 노이즈 필터링: 순수 머지 커밋(`Merge branch ...`) 및 실질적 코드 변경이 없는 빈 커밋을 자동 제외하여 컨텍스트 낭비 방지
  - 실시간 수집 진행률 표시: PyGithub 순회 중 diff 수집 현황을 UI 프로그레스 형태로 피드백
- **하이브리드 AI 포트폴리오 생성 (Gemini)**:
  - ⚡ 표준 고속 모드: 노이즈가 제거된 핵심 커밋(최대 80개)을 Gemini 대용량 컨텍스트로 단 1회 호출하여 15초 내외로 빠른 생성
  - 🔍 정밀 분할 모드 (Map-Reduce): 80개 초과 대규모 커밋(최대 200개)을 40개 단위 청크로 분할 요약(Map)한 뒤 최종 종합(Reduce)하여 프로젝트 전 주기 이력 복원
  - 환각(Hallucination) 방지: 없는 기능이나 수치를 지어내지 않고 실제 diff 로그와 커밋 메시지에만 근거하도록 프롬프트 엄격 제어
- **다양한 포맷의 포트폴리오 내보내기 및 공유**:
  - Notion 네이티브 블록 전송: 마크다운 텍스트를 Notion API 규격에 맞는 블록(헤딩, 코드 블록 언어 매핑, 목록, 인라인 스타일)으로 변환하여 개인 페이지/DB로 즉시 전송
  - GitHub Gist 원클릭 배포: 공개/비공개 Gist로 자동 생성하고 바로가기 공유 링크 발급
  - 웹 & PDF 인쇄용 HTML 다운로드: 모던한 포트폴리오 CSS와 A4 인쇄 최적화 미디어 쿼리가 내장된 단일 HTML 파일 제공
  - 클립보드 원클릭 복사: 생성된 마크다운 원본 코드를 손쉽게 복사할 수 있는 코드 뷰어 제공

## 트러블 슈팅 및 해결

### 1. 대용량 커밋 분석 시 토큰 한도 초과 및 세부 컨텍스트 누락

- **문제**: 초기에는 최근 커밋 50개만 단순 수집하여 처리했으나, 커밋이 많은 장기 프로젝트의 경우 프로젝트 초기의 핵심 아키텍처 설계나 중요한 트러블슈팅 이력이 누락되는 한계 발생. 또한 전체 커밋을 무작정 늘려 단일 프롬프트에 담을 경우 LLM 컨텍스트 부하 및 요약 희석(Lost in the Middle) 현상 발생.
- **해결**: 빈 커밋과 단순 머지를 걸러내는 노이즈 필터링을 구축하고, 80개 이하는 단일 배치로 고속 처리하되 80개 초과 커밋(최대 200개)은 40개 단위 청크로 나누어 핵심 기능/트러블슈팅을 1차 요약한 뒤 최종 5대 섹션으로 병합하는 **하이브리드 Map-Reduce 파이프라인**을 설계하여 정보 누락 없이 전 주기를 복원함.

### 2. 마크다운의 Notion API 블록 변환 및 요청 제약(Rate Limit / Size Limit) 대응

- **문제**: 생성된 마크다운을 Notion으로 내보낼 때, Notion API는 원문 마크다운 문자열을 직접 받지 않고 블록(Block) JSON 객체 배열 형태로 요구함. 또한 1회 요청당 최대 100개 블록 제한과 텍스트 필드당 최대 2,000자 제한이 있어 포트폴리오 분량이 길어질 경우 API 오류 발생.
- **해결**: 자체 마크다운 파서(`markdown_to_blocks`)를 구현하여 헤딩, 불릿, 인라인 서식(Bold/Italic/Code), 코드 블록 언어 매핑을 수행하고, 텍스트가 2,000자를 넘길 경우 자동 청크 분할 및 100개 블록 단위 순차 전송(`_append_remaining`) 로직을 구축하여 안정적으로 Notion 전송 성공.

### 3. LLM API 간헐적 503(Overloaded) 및 429(Rate Limit) 장애 극복

- **문제**: 피크 시간대 Gemini Flash API 호출 시 간헐적으로 `503 Unavailable` 또는 `429 Resource Exhausted` 에러가 발생하여 생성 도중 앱 전체가 중단되는 현상 발생.
- **해결**: 지수 백오프(Exponential Backoff, 2초/4초/8초) 재시도 로직을 도입하고, 재시도 실패 시 상위 모델에서 하위 Flash 모델 체인(`gemini-3.6-flash` → `gemini-2.5-flash` → `gemini-2.0-flash` 등)으로 자동 전환되는 폴백(Fallback) 아키텍처를 구축하여 서비스 가용성을 대폭 향상시킴.

## 배운 점 및 회고

- LLM 애플리케이션 개발 시 단순 프롬프트 작성에 그치지 않고, 데이터 전처리(노이즈 필터링)와 처리 아키텍처(Map-Reduce)가 최종 산출물의 품질과 토큰 효율을 결정짓는 핵심 요소임을 체득했습니다.
- 외부 API(GitHub, Gemini, Notion) 연동 시 발생하는 다양한 제약(Rate Limit, Payload 제한, 서버 장애)에 대비한 재시도, 폴백, 청킹 등 방어적 아키텍처 설계의 중요성을 깊이 이해하게 되었습니다.
- 기획부터 UI 개발, LLM 파이프라인, 배포 연동까지 1인 개발로 전 과정을 완수하며 엔드투엔드 프로덕트 구축 역량을 크게 성장시킬 수 있었습니다.
