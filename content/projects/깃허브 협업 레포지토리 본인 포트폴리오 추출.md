## 프로젝트 소개

GitFolio Generator는 GitHub 저장소의 커밋 내역과 PR diff 데이터를 수집하여 Google Gemini API를 활용해 한국어 마크다운 포트폴리오를 자동 작성해 주는 로컬 Streamlit 웹 애플리케이션입니다.

- **주요 기술 스택**: Python, Streamlit, PyGithub, Google Gemini API
- **주요 기능**: GitHub 데이터 자동 수집, 노이즈 커밋 필터링, 하이브리드 모드(표준 모드 / Map-Reduce 정밀 모드) 기반 LLM 포트폴리오 생성, 다양한 포맷(Markdown, HTML, GitHub Gist, Notion) 내보내기 지원

## 본인 역할

`wnsgk0509` 개발자는 해당 프로젝트의 초기 아키텍처 설계부터 전체 모듈 개발 및 기능 고도화를 전담하였습니다.

- **초기 프로젝트 구조 구축**: Streamlit 기반 UI(`app.py`) 구축 및 데이터 추출기(`src/github_extractor.py`), LLM 연동기(`src/llm_generator.py`) 초기 구현
- **다중 내보내기 파이프라인 개발**: 포트폴리오 결과를 다양하게 활용할 수 있도록 HTML 렌더러(`src/html_exporter.py`), Gist 배포 모듈(`src/gist_exporter.py`), Notion 블록 변환 및 API 전송 모듈(`src/notion_exporter.py`) 구현
- **대용량 커밋 분석을 위한 하이브리드 처리 로직 개발**: 커밋 개수에 따라 단일 호출 분석과 Map-Reduce 분할 분석을 선택해 처리하는 하이브리드 생성 구조 추가

## 핵심 기능

- **GitHub 추출 및 노이즈 필터링**: PyGithub를 이용해 README, 커밋 내역, PR 및 diff 데이터를 가져오며 단순 머지 커밋이나 변경사항 없는 노이즈 커밋을 자동 제외
- **하이브리드 포트폴리오 분석 모드**:
  - **표준 고속 모드**: 최근 유의미한 커밋(최대 80개)을 Gemini의 대용량 컨텍스트로 한 번에 전달하여 빠른 포트폴리오 생성 (~15초)
  - **정밀 분할 모드 (Map-Reduce)**: 커밋 수가 많거나 초기 아키텍처부터 전체 분석이 필요할 때, 최대 200개 커밋을 40개 단위 청크로 분할 요약(Map)한 뒤 최종 종합(Reduce)하여 포트폴리오 작성 (~40초)
- **다양한 형태의 내보내기 (Export) 지원**:
  - **Markdown 파일 다운로드 & 클립보드 복사**: 기본 `.md` 파일 다운로드 및 코드 블록 원클릭 복사
  - **웹/PDF 인쇄용 HTML 다운로드**: 브라우저 인쇄(`Ctrl + P`)를 통해 PDF 변환이 가능한 독립형 HTML 제공
  - **GitHub Gist 자동 배포**: 외부 공유용 Gist URL 생성
  - **Notion 블록 자동 전송**: Notion API를 활용해 네이티브 블록 형태로 지정된 Notion 페이지/데이터베이스로 직접 포트폴리오 전송

## 트러블 슈팅 및 해결

### 대용량 커밋 내역 및 Diff 처리 시 컨텍스트 한계 및 세부 분석 누락 문제

- **문제 원인**: 초기 구조에서는 분석할 커밋 내역과 diff 패치를 단일 프롬프트로만 전달하여 처리했기 때문에, 저장소의 커밋 수가 많아지거나 초기 아키텍처부터 전체 내역을 분석해야 할 경우 단일 호출 용량 한계에 부딪히거나 개별 커밋의 핵심 기능/트러블슈팅 상세 내역이 유실될 위험이 있었습니다.
- **해결 방안**: 커밋 수 및 분석 깊이에 맞춰 유연하게 대응할 수 있도록 커밋 개수 기준의 하이브리드 모드 파이프라인을 구축했습니다.
  - `src/github_extractor.py`에 `DEFAULT_MAX_COMMITS`, `DEEP_MAX_COMMITS` 등의 상수를 정의하고 필터링 로직을 강화했습니다.
  - `src/llm_generator.py`에 Map-Reduce 프롬프트 처리 로직을 구현하여 40개 단위 청크로 분할해 1차 요약(Map)을 수행한 뒤, 해당 요약본들을 수집하여 최종 5개 섹션 포트폴리오로 종합(Reduce)하는 방식을 도입했습니다.
  - Streamlit UI(`app.py`)에 모드 선택 라디오 버튼을 도입하여 사용자가 상황에 맞춰 '표준 고속 모드'와 '정밀 분할 모드'를 선택할 수 있게 했습니다.

## 배운 점 및 회고

- **LLM 컨텍스트 한계 극복을 위한 Map-Reduce 설계**: 대용량 코드 diff와 커밋 내역을 분석할 때 단순 프롬프트 전달 이상의 구조적 처리(청크 분할 및 요약 후 종합)가 필요함을 체득하고 이를 코드화했습니다.
- **다양한 외부 API 연동 경험**: GitHub REST API(PyGithub), Gemini API 뿐만 아니라 Notion API를 통한 네이티브 블록 변환 및 전송, Gist API 연동까지 확장하여 단일 결과물을 다양한 플랫폼으로 내보내는 파이프라인 구축 능력을 길렀습니다.
- **데이터 한계**: 커밋/PR 데이터에서 단위 테스트 작성 여부나 automated CI/CD 파이프라인 구성 등의 내역은 확인하기 어렵습니다.
