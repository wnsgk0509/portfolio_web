# 1lev_up — 최소 습관 & 루틴 관리 시스템

URL: https://github.com/wnsgk0509/1lev_up
도메인: https://1lev-up.vercel.app/
기술: React 19, TypeScript, Tailwind CSS, Supabase, Vite, PWA, Workbox, Canvas-Confetti
날짜: 2026년 11월
팀구성: 개인 프로젝트 (1인 개발)
역할: 전 기능 1인 개발 (기획/설계, 프론트엔드 UI/UX, 오프라인 퍼스트 큐 아키텍처, Supabase BaaS 연동, 번들 최적화)

## 프로젝트 소개

**1lev_up**은 《아주 작은 습관의 힘》과 《원씽(The ONE Thing)》의 핵심 원리를 적용하여, 컨디션이 좋지 않은 날에도 무너지지 않고 지킬 수 있는 **'최소 실행 가능 루틴(Minimum Viable Routine)'**을 세우고 관리하는 웹 서비스입니다.

의사결정 피로를 줄이기 위해 전날 밤 지정한 최우선 과업(One Thing)을 다음 날 아침 자동 연동하며, 지하철 등 네트워크 단절 상황에서도 데이터 유실 없이 안정적으로 동작하는 **오프라인-퍼스트 PWA 웹 애플리케이션**입니다.

- **Frontend & App**: React 19, TypeScript, Tailwind CSS, Vite
- **Offline & PWA**: Vite PWA Plugin, Workbox Service Worker, 멱등성 기반 Offline Queue
- **Backend / Cloud**: Supabase (PostgreSQL, Row Level Security, Auth)
- **Interactive UI**: Canvas-Confetti, Lucide Icons, Mobile Responsive Layout

## 본인 역할

기획 및 인터페이스 설계부터 프론트엔드 구현, 오프라인 큐 동기화 엔진, Supabase 클라우드 연동, 번들링 최적화까지 **전 과정을 1인 주도 개발**하였습니다.

- **최소 루틴 UX 기획 및 프론트엔드 전 기능 개발**: React 19 및 Tailwind CSS 기반의 메인 타임라인 대시보드, The ONE Thing 카드, 독서 서재, 월간 달성률 통계 뷰 및 모달 컴포넌트 전체 구현
- **오프라인 퍼스트(Offline-First) 동기화 아키텍처 구축**: 네트워크 단절 시에도 데이터 유실을 방지하는 멱등성(Idempotent) 기반 로컬 큐(`offlineQueue.ts`) 설계 및 네트워크 재연결 시 자동 플러시(Auto-flush) 파이프라인 개발
- **Supabase BaaS 연동 및 스마트 데이터 마이그레이션**: 이메일 및 소셜 인증 체계 구축, 비회원 로컬 스토리지 데이터를 로그인 시 클라우드로 안전하게 병합하는 마이그레이션 엔진 구현
- **PWA 및 번들링 최적화**: Workbox 기반 서비스 워커 오프라인 캐싱, `manualChunks` 및 `React.lazy`를 통한 코드 분할로 초기 번들 용량 93.5% 감축 달성

## 핵심 기능

- **오늘의 The ONE Thing**:
  - 전날 밤 설정한 최우선 목표 자동 연동으로 아침 의사결정 피로도 제로화
  - 컨디션 저하 시 원클릭 '독서 15분' 대체 루틴 전환
  - 과업 달성 시 콘페티(Confetti) 축하 인터랙션 제공
- **타임라인 기반 최소 루틴 체크리스트**:
  - 기상, 산책, 몰입 타이머 등 기본 추천 루틴 및 실시간 인라인 편집
  - 드래그/클릭 기반 순서 변경 및 커스텀 루틴 추가·삭제 관리
- **독서 서재 & 하루 회고**:
  - 감명 깊은 문장과 인사이트를 기록하고 검색하는 개인 독서 서재
  - 기분 상태(Emoji) 체크 및 하루 일기 기록, 취침 전 내일의 One Thing 사전 예약
- **동기부여 및 통계**:
  - 연속 달성 스트릭(Streak) 카운터 및 월간 캘린더 달성 현황 시각화
  - 기기 변경에 대비한 JSON 규격 데이터 내보내기/가져오기 백업 지원
- **오프라인-퍼스트 PWA & 클라우드 동기화**:
  - 서비스 워커를 통한 홈화면 앱 설치(A2HS) 및 완벽한 오프라인 실행 지원
  - 네트워크 단절 시 로컬 큐에 임시 저장 후, 재연결 시 Supabase로 자동 일괄 동기화(Auto-flush)

## 트러블 슈팅 및 해결

### 1. 단일 번들 크기 과다로 인한 초기 로딩 지연 및 빌드 경고 해결

- **문제**: 초기 빌드 시 모든 컴포넌트와 외부 라이브러리가 단일 엔트리로 묶여 번들 크기가 537kB(gzip 153kB)를 초과하였고, 모바일 환경에서 초기 로딩 지연 및 청크 경고 발생
- **원인**: 비초기 진입 화면(통계 뷰, 독서 서재)과 무거운 모달 컴포넌트(`AuthModal`, `EveningTimerModal` 등)가 지연 로딩 없이 일괄 로드됨
- **해결**: `vite.config.ts`의 `build.rollupOptions.output.manualChunks`로 벤더 번들(`react-vendor`, `supabase-vendor`, `ui-vendor`)을 분리하고, 비초기 컴포넌트에 `React.lazy`와 `Suspense`를 적용하여 코드 분할(Code Splitting) 단행
- **결과**: 메인 엔트리 번들 크기가 **537.10kB에서 34.79kB로 약 93.5% 대폭 감축**되었으며 초기 로딩 반응 속도 획기적 개선

### 2. 오프라인 상태에서 루틴 변경 시 데이터 유실 및 클라우드 동기화 실패 문제

- **문제**: 지하철 등 네트워크 미연결 환경에서 루틴을 체크하거나 수정할 경우 Supabase API 요청이 실패하여 변경 데이터가 유실되거나 상태 불일치 발생
- **원인**: 온라인 상태만 가정한 동기식 클라우드 전송 구조로 인해 네트워크 에러 시 복구 메커니즘 부재
- **해결**: 멱등성(Idempotency)을 보장하는 로컬 오프라인 큐 서비스(`offlineQueue.ts`)를 구축하여 미전송 작업을 로컬에 저장하고, 브라우저 `window.online` 이벤트를 감지하여 재연결 시 `flushOfflineQueue`가 누적된 요청을 자동 일괄 반영(Auto-flush)하도록 구현. 상단 헤더에 동기화 펜딩 배지 노출
- **결과**: 오프라인 상태에서도 끊김 없는 사용성을 제공하고, 네트워크 복구 즉시 자동 동기화되어 데이터 유실률 0% 달성

### 3. 미활성화된 OAuth 로그인 시도 시 로우 레벨 API 에러 노출

- **문제**: 소셜 로그인 프로바이더가 활성화되지 않은 상태에서 구글/카카오 로그인 클릭 시 `provider is not enabled` 같은 기술적 에러 문구가 화면에 그대로 노출되어 사용자 혼란 초래
- **원인**: 백엔드 API 에러 메시지가 클라이언트 UI 레이어에서 정제되지 않고 다이렉트로 전달됨
- **해결**: `AuthModal.tsx`에 에러 파싱 체인을 신설하여 프로바이더 미활성화 오류 감지 시 즉시 사용 가능한 '이메일 간편 로그인'으로 우회 안내하는 친절한 피드백 메시지로 자동 변환 처리
- **결과**: 예외 상황 발생 시 사용자 이탈 방지 및 즉각적인 서비스 테스트 경로 확보

## 배운 점 및 회고

- **오프라인-퍼스트(Offline-First) 설계 역량 강화**: 단순한 웹 개발을 넘어 오프라인 큐와 재연결 이벤트 제어를 구현하며, 열악한 네트워크 환경에서도 데이터 무결성과 사용자 경험을 보장하는 프론트엔드 아키텍처를 체득했습니다.
- **번들 최적화와 초기 로딩 UX 체감**: `manualChunks` 설정과 동적 임포트(`React.lazy`)를 통해 번들 크기를 90% 이상 감축하는 과정을 직접 경험하며, 성능 최적화가 모바일 웹 사용자 경험에 미치는 실질적 영향을 깊이 체감했습니다.
- **사용자 중심의 친절한 예외 처리 설계**: 기술적 오류를 그대로 노출하지 않고 대안 경로(이메일 로그인)로 부드럽게 유도하는 UX 디테일이 서비스 신뢰도에 얼마나 중요한지 확인했습니다.
