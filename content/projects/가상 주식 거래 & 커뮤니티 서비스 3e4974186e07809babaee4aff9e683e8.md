## 프로젝트 소개

**Frade (프레이드)**는 실시간 가상 주식 거래 및 모의투자 서비스와 투자자 간 정보를 공유할 수 있는 투자 커뮤니티 플랫폼입니다.

- **기술 스택**: Java 17, Spring Framework (v5.3.37), MyBatis (v3.5.16), Oracle DB, JSP/JSTL, JavaScript (ES6+), AJAX, Bootstrap
- **협업 방식**: Git / GitHub (Gitflow 브랜치 전략: `main` -> `dev` -> `feature_*`), [FEAT]/[FIX]/[CHORE] 커밋 컨벤션 준수, 전사 통일 REST API Response Wrapper 규격 적용

## 본인 역할

프로젝트 리더 및 커뮤니티 도메인 전반의 개발을 담당하였습니다. 백엔드 컨트롤러/서비스/DAO/MyBatis 쿼리부터 프론트엔드 JSP 뷰 및 AJAX 비동기 로직까지 풀스택으로 구현하였습니다.

- **커뮤니티 도메인 전담 구현**: 게시글 CRUD, 댓글 CRUD, 게시글/댓글 페이징, 게시글 파일 업로드 및 미리보기/다운로드
- **조회수 제어 로직 구현**: 로그인 유저별/비로그인 게스트별 쿠키 분리를 통한 중복 조회수 증가 방지
- **뉴스 서비스 매핑**: `NewsController` 작성 및 뉴스 목록 페이지, 메인 대시보드 TOP 5 뉴스 연동
- **공통 API 규격 및 인증 연동**: `RestApiResponse` 표준 응답 객체 적용 및 `LoginManager` 세션 기반 본인 검증 로직 연결

## 핵심 기능

- **게시글 관리 및 DB 페이징**
    - 게시글 작성, 상세 조회, 수정, 삭제 기능 구현.
    - Oracle DB Dynamic SQL 및 `OFFSET ... FETCH NEXT ... ROWS ONLY` 구문을 활용한 게시글 목록 페이징 및 검색(제목, 작성자) 처리.
    - `LoginManager` 기반 세션 검증을 통해 작성자 본인만 수정/삭제가 가능하도록 권한 제어.
- **댓글 시스템 (REST API & 비동기 처리)**
    - `@RestController` 기반의 RESTful API(`RestCommunityController`) 구축.
    - AJAX 비동기 통신을 통한 댓글 작성, 페이징 목록 조회 및 삭제 처리.
    - 댓글 단건 조회 및 본인 확인 쿼리(`isWriterComment`)를 통한 안전한 삭제 검증.
- **첨부파일 관리 (업로드 / 다운로드 / 미리보기)**
    - MultipartFile을 활용한 첨부파일 로컬 저장소 저장 및 DB 파일명 관리.
    - 이미지 파일(jpg, png, webp 등) 자동 미리보기 및 일반 파일/PDF 미리보기 및 다운로드 기능 제공.
    - 게시글 수정 시 기존 파일 유지, 삭제 선택 처리 및 새 파일 교체 업로드 로직 구현.
- **주식 뉴스 연동**
    - `NewsController`를 구축하여 뉴스 메인 화면(`news/news.jsp`) 연결 및 메인 대시보드 내 주식 뉴스 더보기 링크 연동.

## 트러블 슈팅 및 해결

### 1. 동일 브라우저 내 계정 전환 시 게시글 조회수 카운팅 오류

- **문제**: 게시글 상세 조회 시 단일 쿠키명(`viewedPosts`)만 사용하여 읽은 글 번호를 저장했기 때문에, 동일한 브라우저에서 A 계정 로그아웃 후 B 계정으로 로그인하여 같은 글을 조회해도 조회수가 증가하지 않는 문제 발생.
- **해결**: `LoginManager.getLoginUserNum(request)`를 사용하여 로그인 유저별 쿠키명(`viewedPosts_u{userNum}`)과 비로그인 게스트용 쿠키명(`viewedPosts_guest`)을 구분 생성하도록 수정. 계정이 달라지면 독립된 쿠키로 검증되어 정상적으로 조회수가 카운팅되도록 개선 (`be07adbb22adcad73d62a62f5a2f019ce87f09f4`).

### 2. 댓글 삭제 시 댓글이 1개 남았을 때 비동기 화면 미갱신 버그

- **문제**: 상세 페이지에서 댓글을 삭제할 때, 남은 댓글이 1개인 상태에서 삭제 요청을 보낼 경우 서버에서 성공 응답(`suc_002`)을 받아도 화면상에서 댓글이 바로 사라지지 않고 새로고침을 해야만 반영되는 버그 발생.
- **해결**: `detail.jsp`의 비동기 fetch 콜백 부분에서 댓글 삭제 성공 코드 `suc_002` 수신 시 `commentCount` 엘리먼트 요소를 `0`으로 초기화하고, 댓글 목록 리스트를 빈 배열(`[]`)로 재렌더링하며 페이징 영역(`paging.innerHTML = ''`)을 비우도록 수정 (`0a21f20605d387bbfeed6bca0fb90f4efb619791`).

### 3. 게시글 수정 시 기존 첨부파일 삭제 및 교체 로직 오류

- **문제**: 게시글 수정 중 새 첨부파일을 업로드할 때 기존 파일과의 연동 처리가 불명확하여 파일이 누락되거나 디스크 삭제 처리가 정상 작동하지 않는 현상 발생.
- **해결**: `PostServiceImpl`의 `updatePost` 메서드 내에 `deleteExistingFiles` 파라미터를 추가하고, 기존 파일 삭제 체크박스 선택 여부 및 새 파일 업로드 유무에 따른 조건별 디스크 파일 삭제 및 DB 경로 업데이트 로직을 명확히 분기하여 안정성 확보 (`bdb1b03cdfdbcd10557de5f22cb020825f1f0218`).

## 배운 점 및 회고

- **REST API 표준 응답 객체의 필요성**: 프론트엔드와 백엔드 간 REST API 통신 시 통일된 JSON 껍데기 구조(`RestApiResponse`)와 `ResultCode` Enum을 활용함으로써 예외 상황 및 비동기 처리 시 에러 핸들링 효율을 극대화할 수 있었습니다.
- **쿠키 및 세션 기반 권한 검증**: 단순히 뷰 단에서 버튼을 숨기는 것을 넘어 백엔드 컨트롤러 및 SQL 단에서 2중으로 작성자 유저 번호를 비교 검증하는 보안적 접근의 중요성을 배웠습니다.
- **데이터 미비 항목**: 정교한 성능 측정 지표(예: 쿼리 속도 개선율 등)나 타 팀원의 구체적인 작업 내역은 커밋/PR 데이터에서 확인하기 어렵다.
