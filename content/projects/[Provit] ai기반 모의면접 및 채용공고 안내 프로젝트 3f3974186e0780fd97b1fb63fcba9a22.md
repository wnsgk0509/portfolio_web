# Provit — AI 기반 모의면접 및 채용공고 추천 플랫폼

URL: https://github.com/wnsgk0509/provit
도메인: https://provit-sigma.vercel.app/
기술: Java 17, Spring Framework (MVC), MyBatis, OracleDB, React 19, Vite, Vercel
날짜: 2026년 9월 15일 → 2026년 10월 8일
팀구성: 협업 (4명)
역할: 기술팀장 · DB 전체 스키마 설계, Git-Flow/PR 코드 리뷰 주도, 채용공고 크롤러·맞춤 추천·사주 Fallback 풀스택 구현 및 Vercel 배포 파이프라인 구축

## 프로젝트 소개

**Provit(프로빗)**은 구직자가 AI 모의면접, 서류 첨삭, 실시간 채용공고 탐색 및 맞춤 추천을 한 곳에서 진행할 수 있도록 기획한 **Spring Framework(MVC) + React 19 기반 풀스택 취업 지원 플랫폼**입니다.

- **Backend**: Spring Framework (MVC) 5.3.39 (JDK 17), Apache Tomcat 9.0.x, MyBatis, HikariCP, Jsoup
- **Database**: OracleDB 19c (2,178개 표준 직무 시드 데이터 및 스키마 설계)
- **Frontend**: React 19, Vite, Axios, React Router, Lucide Icons, Bootstrap
- **Deployment & Collaboration**: Vercel (CI/CD & Reverse Proxy), ngrok (Backend Tunneling), Git-Flow

## 기획 및 문제 정의

- **해결하려는 문제**: 취업 준비생이 채용공고 탐색, 직무 매칭, 모의면접 준비를 여러 플랫폼에 흩어져 수행하는 비효율과, 이력서가 아직 없는 초기 가입자에게 공고 추천이 비어 보이는 콜드 스타트 문제를 해결하고자 했습니다.
- **설계 전략**: 외부 크롤링·외부 API 장애가 전체 서비스 중단으로 번지지 않도록 **비동기 배치(`CompletableFuture`) + 로컬 Fallback 엔진(`LocalSazuEngine`) + 다단계 추천 Fallback(대표 이력서 → 기본 직무 → 인기 공고)** 구조를 선제적으로 설계했습니다.

## 본인 역할

4인 팀의 **기술팀장**이자 백엔드·풀스택 핵심 개발자로서 초기 환경 구축, Git-Flow 브랜치 전략·PR 코드 리뷰, 전체 데이터베이스 스키마 설계부터 채용공고·운세(사주) 도메인 풀스택 구현 및 배포 프록시 구성까지 엔드투엔드로 전담했습니다.

- **기술팀장 · 협업 표준 및 PR 코드 리뷰 주도**: 공통 개발 환경 정리, Git-Flow 브랜치 전략 수립, PR 단위 코드 리뷰를 통해 팀 병목과 Windows Git 대소문자 충돌을 해소
- **DB 스키마 설계 및 기초 데이터 구축**: 전체 테이블·시퀀스·제약조건 설계 및 사람인 **2,178개** 표준 직무 시드 데이터 구축
- **채용공고 도메인 풀스택 구현**: Jsoup 기반 채용공고 크롤러·자동 배치 스케줄러 개발, 조건별 검색·필터링·스크랩 REST API 및 React UI 구현
- **다단계 맞춤형 채용공고 추천 설계**: 회원 대표 이력서 직무 우선 매칭 → 미등록 시 기본 희망 직무·인기 공고로 이어지는 Fallback 추천 알고리즘 및 `EXISTS` 하위 직무 검색 구현
- **외부 API 무중단 Fallback 엔진 구축**: 외부 사주 API 연동 및 키 미설정·무료 플랜 제한 시 자동 전환되는 자체 로컬 만세력 엔진(`LocalSazuEngine`) 구현
- **공통 파일 업로드 모듈 개발**: `FileCategory` Enum(`PORTFOLIO`, `POST`, `PROFILE`) 기반 확장자·용량 검증 및 저장 경로 분리
- **배포 통신 파이프라인 & 협업 환경 안정화**: `vercel.json` 리버스 프록시·Spring 5.3 전역 CORS 설정 및 Windows Git 대소문자 중복 파일 충돌 전수 정리

## 핵심 기능

- **프론트엔드 Vercel 배포 및 리버스 프록시 연동**:
  - Vercel Edge 기반 React 19 SPA 정적 호스팅 및 자동 CI/CD 파이프라인 구축
  - `vercel.json` Rewrites 규칙으로 SPA 새로고침 404 방지 및 `/api/**` 백엔드 API 리버스 프록시 라우팅 적용
- **채용공고 웹 크롤링 및 자동 배치 스케줄링**:
  - `SaraminCrawler`로 실시간 채용공고 수집 후 `T_RECRUITMENT` 테이블 동기화
  - `@Scheduled` 및 `ContextRefreshedEvent` 비동기 실행으로 마감 공고 자동 비활성화 및 **180일** 이상 미스크랩 공고 자동 정리(Purge)
- **조건별 채용공고 검색 및 다단계 맞춤 추천**:
  - 대표 이력서 직무 우선 적용 → 기본 설정 직무 → 인기 공고 순 Fallback 추천 로직으로 콜드 스타트 해소
  - 대분류 직군 선택 시 `EXISTS` 서브쿼리로 하위 세부 직무까지 확장 매칭 및 최신순/마감임박순 정렬 제공
- **운세(사주) 기반 직무 추천 & 무중단 Fallback**:
  - 외부 만세력 API 상태 판별 후 장애·미설정 시 자체 `LocalSazuEngine`으로 자동 분기해 무중단 응답 보장
- **공고 스크랩·관리자 제어 및 공통 파일 업로드**:
  - `T_JOB_SCRAP` 북마크 동시성 제어, `ADMIN` 권한 검증 기반 수동 동기화 API, `FileCategory` Enum 파일 검증 모듈 구현

## 기술 검증 요약

- **기동 안정성 검증**: 서버 부팅 시 동기 크롤링으로 인한 Tomcat 타임아웃·HikariCP 불안정을 `CompletableFuture.runAsync()` 비동기 지연 실행으로 분리해 기동 실패 0건 확보
- **동시성·무결성 검증**: 중복 스크랩 및 크롤링 재적재 시 PK/UNIQUE 충돌을 Oracle `MERGE INTO` + `DataIntegrityViolationException` 멱등성 처리로 차단
- **배포 네트워크 검증**: Vercel + ngrok 실배포 환경에서 발생한 POST 403 CORS 차단 및 SPA 새로고침 404를 Spring `allowed-origin-patterns`와 `vercel.json` Rewrites로 완전 해소
- **외부 의존성 장애 검증**: 외부 API 키 미설정 및 무료 키(`sazu_free_`) 조건에서 `LocalSazuEngine` 자동 Fallback 동작 검증

## 기술 검증 및 트러블 슈팅

### 1. 외부 운세 API 미설정 및 무료 키 제한에 따른 서비스 중단 방지

- **문제**: 외부 사주 API 키가 미설정되거나 무료 샌드박스 키(`sazu_free_`)일 경우 외부 호출 실패로 서비스 전체 에러가 발생할 위험이 있었습니다.
- **원인**: 외부 API 가용성에 강결합된 단일 호출 구조로 인해 키 상태 및 플랜 제한에 대한 방어 분기가 없었습니다.
- **해결**: `SazuApiClient`에 `isConfigured()`, `isFreeTier()` 검증을 추가하고, 미설정·무료 키 감지 시 자체 구현한 `LocalSazuEngine`으로 자동 분기하도록 `FortuneServiceImpl`에 Fallback 패턴을 적용했습니다.
- **결과**: 외부 API 장애나 키 제한 환경에서도 중단 없이 사주 기반 직무 추천 기능을 정상 응답하도록 가용성을 확보했습니다.

### 2. 서버 기동 시 동기 크롤링으로 인한 Tomcat 부팅 지연 및 커넥션 풀 에러

- **문제**: Spring 컨텍스트 초기화(`ContextRefreshedEvent`) 시점에 웹 크롤링을 동기 실행하자 서버 기동 타임아웃과 HikariCP 커넥션 풀 불안정 에러가 발생했습니다.
- **원인**: 무거운 외부 HTTP 크롤링 I/O 작업이 메인 부팅 스레드를 점유하여 WAS 초기화 완료를 블로킹했습니다.
- **해결**: `RecruitmentScheduler`에 `CompletableFuture.runAsync()`를 적용해 초기 크롤링을 별도 비동기 스레드로 분리하고, 커넥션 풀 안정화 이후 지연 실행되도록 개선했습니다.
- **결과**: Tomcat 서버가 지연 없이 즉시 정상 기동되며, 백그라운드에서 채용공고 초기 적재가 안정적으로 완료됨을 확인했습니다.

### 3. 공고 스크랩 토글 및 크롤링 동기화 시 DB 제약조건 위반

- **문제**: 동시 스크랩 요청 또는 크롤링 배치 재실행 시 PK/UNIQUE 제약조건 위반 예외가 발생했습니다.
- **원인**: 선조회(SELECT) 후 삽입(INSERT) 방식의 레이스 컨디션으로 인해 동시 요청이 동일 키를 중복 삽입하려 시도했습니다.
- **해결**: MyBatis XML에 Oracle `MERGE INTO` 업서트 구문을 적용하고, 서비스 계층에서 `DataIntegrityViolationException`을 처리해 멱등성을 보장했습니다.
- **결과**: 반복적인 크롤링 동기화 및 연속 스크랩 클릭 테스트에서도 제약조건 충돌 없이 데이터 무결성을 유지했습니다.

### 4. 배포 환경(Vercel/ngrok) 연동 시 POST 요청 403 CORS 차단 및 SPA 새로고침 404

- **문제**: 실제 배포 도메인에서 GET 요청은 동작했으나 로그인·회원가입 등 POST 요청 시 `403 Forbidden (Invalid CORS request)`이 발생했고, `/jobs`·`/interview` 경로 새로고침 시 404 에러가 발생했습니다.
- **원인**: 백엔드 `servlet-context.xml`에 로컬 오리진(`localhost:5173`)만 허용되어 있었으며, 정적 호스팅 환경에 SPA 라우트 리다이렉트 규칙이 누락되었습니다.
- **해결**: Spring 5.3 `allowed-origin-patterns`로 허용 도메인을 안전하게 구성하고, `vercel.json` Rewrites에 `/api/**` 리버스 프록시 및 `/(.*) -> /index.html` SPA 라우팅 규칙을 적용해 Same-Origin 통신 환경을 구축했습니다.
- **결과**: 배포 환경에서 인증·POST API 호출 및 모든 세부 라우트 새로고침이 오류 없이 정상 동작함을 검증했습니다.

### 5. Windows Git 대소문자 파일명 중복 충돌로 인한 팀 빌드 실패

- **문제**: Windows(대소문자 미구분) 환경에서 `UserDao.java`와 `UserDAO.java`가 원격 저장소에 중복 추적되어 팀원 간 머지 및 빌드가 실패했습니다.
- **원인**: 파일명 대소문자 변경 시 Git 인덱스 정리(`git mv`) 없이 커밋되어 OS별 파일 시스템 불일치가 누적되었습니다.
- **해결**: 중복 추적된 DTO/DAO 파일을 전수 조사해 단일화하고, 팀 내 표준 네이밍 컨벤션을 재정립했습니다.
- **결과**: 팀 전체의 클린 클론 및 빌드 파이프라인이 충돌 없이 일관되게 통과하도록 안정화했습니다.

## 배운 점 및 회고

- **방어적 아키텍처와 Fallback 설계의 중요성**: 외부 API와 크롤링처럼 통제 불가능한 외부 의존성을 다룰 때, 로컬 Fallback 엔진과 비동기 격리 설계가 실제 서비스 안정성을 결정한다는 점을 체득했습니다.
- **3-Tier 배포 네트워크 흐름 체득**: Frontend CDN(Vercel) – Reverse Proxy – WAS(Tomcat/Spring) – DB(Oracle) 전 구간의 CORS·라우팅·동시성 이슈를 직접 디버깅하며 실무 배포 감각을 키웠습니다.
- **협업 컨벤션의 가치**: Windows/macOS 혼용 팀 프로젝트에서 네이밍 규칙과 Git 인덱스 관리가 곧 빌드 안정성임을 경험했습니다.
